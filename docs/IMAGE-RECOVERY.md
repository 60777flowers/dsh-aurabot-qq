# 旧图片被拒绝后，下一轮仍能聊天

某些模型会检查整段历史里的图片。一张旧图被拒绝后，即使接下来只发文字，也可能连续很多轮没有回复。

「图片上下文恢复」默认随 Aurabot 启动，不需要填参数。它识别 MiniMax 返回的明确输入图片拒绝：`PI_AI_ERROR`、`input new_sensitive`、`image is sensitive`、`1026`，然后让失败这一轮及以前的输入图片退出后续请求。

- 不重试或补发失败的那一轮，不把被拒绝的图片换渠道重新提交。
- 保留同一个会话、全部文字历史和原始图片文件；只写入宿主已有的 `image/offload` 事件。
- 新一轮新增的图片不受影响。旧图不再自动进入模型上下文；需要重新看图时应明确重新提供。
- 网络错误、限流、普通文本审核、成功的轮次以及非 Aurabot 聊天会话都不处理。

上游给出的消息/图片序号属于经过转换的请求，不能可靠地对应到原始聊天记录。因此恢复会卸载失败时保留的全部输入图片，而不猜测哪张有问题。模型后续请求会看到宿主生成的卸载说明；已有的文字描述仍然保留。

模块监听回合结束，不增加轮询、计时器、模型调用或聊天提示。它通过异步会话观察接口读取事件，在宿主发布事件之后提交恢复，避免重入；读取结束释放观察对象。已经卸载的图片不会重复处理，恢复过程中新增的图片受失败事件的序号边界保护。

在旧版 Aurabot 上也可把同一模块作为用户模块加载，无需重启 DSH、改模型或清空会话。以后使用带该内置模块的版本时，可移除同名用户模块以使用内置实现。
